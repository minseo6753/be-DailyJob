# be-DailyJob 

> 이 회고는 작업량을 보고하기 위한 문서가 아니라, 
> 오늘 내가 어떤 판단을 했고 어떤 개발 행동을 반복하거나 바꿔야 하는지 확인하기 위한 기록입니다. 
> 각 항목은 길게 쓰기보다, 사실/판단/근거/다음 행동이 드러나게 구체적으로 작성하세요.

### 1. 오늘 완료한 것
- 오늘 실제로 끝낸 기능/수정/학습: 코드 리뷰, 리팩토링, UI/UX 개선, 진행 중 배송 조회 기능 구현 
- (오늘의 목표 중에서) 아직 끝내지 못한 부분: 실시간 위치 처리 파트 공부

### 2. 오늘 가장 의미있었던 기술적 판단
- 내가 내린 판단: 사용자 화면에 시간이 UTC 기준으로 표시되는 문제를 프론트엔드에서 파싱하는 방법으로 고침
- 그렇게 판단한 이유: 백엔드 측에서의 시간 저장은 이미 UTC로 통일되어 있고 DTO에서 변환해서 보내주는 방법은 DTO의 갯수로 인해 수정 비용이 높다.
- 고려했지만 선택하지 않은 대안: 백엔드에서 오프셋을 포함해 직렬화하여 전달
- 이 판단이 코드 품질/테스트/유지보수에 미친 영향: 수정범위를 줄여 유지보수 비용을 낮춤, 시각 처리 로직 단일화, 화면 간 불일치 제거

### 3. 가장 막혔던 문제와 해결 과정
- 문제 상황 또는 증상: 추적 화면에서 홈 버튼으로 이동하면 진행 중 배송 요약이 안 뜨고, 브라우저 새로고침해야 나옴
- 처음 추측한 원인: 홈으로의 클라이언트 이동 시 라우트가 리마운트되며 조회 훅이 아예 안 도는 라우팅 문제로 의심
- 원인을 확인하기 위해 시도한 방법: 전역 QueryClient 설정(lib/queryClient.ts)과 훅 옵션 확인 → 기본 staleTime 30초 발견
- 실제 원인: staleTime 30초라 직전에 캐시된 "진행 중 없음"(null)을 재사용해 재요청을 안 함(+ 라이더가 서버에서 바꾸는 상태는 고객 쪽 mutation이 없어 캐시 무효화도 안 됨)
- 해결 방법: 홈 쿼리에 refetchOnMount:'always' 부여 + 로딩 판정을 isPending→isFetching으로 바꿔 잘못된 상태 깜빡임 제거
- 다음에 비슷한 문제가 생기면 먼저 확인할 것: "새로고침하면 되는데 화면 전환은 안 됨" 증상은 라우팅이 아니라 React Query의 staleTime/캐시 무효화부터 의심

### 4. 오늘 잘한 행동(개발과 관련된 것)
- 어떤 행동이었는지: 다른 팀원들이 하는 일에도 관심을 가지고 참견한 것
- 그 접근이 도움이 된 이유: 프로젝트의 전체적인 구조나 진행상황을 파악할 수 있었고 지식도 늘었다.
- 다음에도 반복하고 싶은 점: 진행상황 추적하기, 팀원들에게 항상 관심 가지기

### 5. 오늘 아쉬웠던 행동(개발과 관련된 것)
- 비효율적이었던 접근/놓치거나 부족했던 점: 항상 문제를 제기하기만 해서 다른 팀원들에게 일거리를 떠넘긴 것 같다. 되돌아보니 나는 단순한 일만 하고 기술적으로 어렵고 중요한 일은 안 한 것 같다.
- 그렇게 된 원인: 명시적 분업의 부재, 도전정신의 부재
- 다음에는 다르게 해볼 구체적인 행동: 기술적 난제를 찾아서 도전해보기
