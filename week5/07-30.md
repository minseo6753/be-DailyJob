# be-DailyJob 

> 이 회고는 작업량을 보고하기 위한 문서가 아니라, 
> 오늘 내가 어떤 판단을 했고 어떤 개발 행동을 반복하거나 바꿔야 하는지 확인하기 위한 기록입니다. 
> 각 항목은 길게 쓰기보다, 사실/판단/근거/다음 행동이 드러나게 구체적으로 작성하세요.

### 1. 오늘 완료한 것
- 오늘 실제로 끝낸 기능/수정/학습: 라이더 세션 만료 처리 방식 결정, 테스트 컴파일 실패 문제 해결
- (오늘의 목표 중에서) 아직 끝내지 못한 부분: 라이더 도메인 기능 구현

### 2. 오늘 가장 의미있었던 기술적 판단
- 내가 내린 판단: 라이더 세션 만료 처리를 Redis Keyspace 만료 알림으로 결정
- 그렇게 판단한 이유: Redis 를 이미 사용한다. 세션 만료 시에만 작동한다.
- 고려했지만 선택하지 않은 대안: expireAt을 TTL보다 짧게 설정해 상태 전이 후 세션 삭제
- 이 판단이 코드 품질/테스트/유지보수에 미친 영향: 세션은 삭제됐는데 AVAILABLE 상태인 경우를 없앤다. 다만 처리 과정에서 에러 발생 시에는 앞선 상황이 일어나기 때문에 주기적 스윕같은 방안을 추가적으로 고려중이다.

### 3. 가장 막혔던 문제와 해결 과정
- 문제 상황 또는 증상: 테스트 코드 컴파일 실패
- 처음 추측한 원인: import 문 누락
- 원인을 확인하기 위해 시도한 방법: 커밋 히스토리 검사
- 실제 원인: 머지과정에서 한 팀원의 변경사항을 다른 팀원이 복구함
- 해결 방법: 기존의 의도대로 코드 정리
- 다음에 비슷한 문제가 생기면 먼저 확인할 것: 커밋 히스토리

### 4. 오늘 잘한 행동(개발과 관련된 것)
- 어떤 행동이었는지: 통합 테스트에서 실패하는 테스트를 발견하고 담당자에게 보고
- 그 접근이 도움이 된 이유: 테스트 실패 원인을 통해 JVM에 대한 지식을 얻었고 통합 테스트가 성공하게 되었다.
- 다음에도 반복하고 싶은 점: 주기적으로 테스트 실행해보기

### 5. 오늘 아쉬웠던 행동(개발과 관련된 것)
- 비효율적이었던 접근/놓치거나 부족했던 점: 우선순위가 낮은 작업을 오래 붙들고 있어 작업 속도가 느려지고 산출물이 나오지 않음
- 그렇게 된 원인: 우선순위를 명확히 정하지 않음
- 다음에는 다르게 해볼 구체적인 행동: 일이 여러개 있을 때 우선순위를 정하자
