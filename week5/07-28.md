# be-DailyJob 

> 이 회고는 작업량을 보고하기 위한 문서가 아니라, 
> 오늘 내가 어떤 판단을 했고 어떤 개발 행동을 반복하거나 바꿔야 하는지 확인하기 위한 기록입니다. 
> 각 항목은 길게 쓰기보다, 사실/판단/근거/다음 행동이 드러나게 구체적으로 작성하세요.

### 1. 오늘 완료한 것
- 오늘 실제로 끝낸 기능/수정/학습: 엔티티 구현 코드 검토 및 문서 작성, 배차 동시성 ADR 문서 작성
- (오늘의 목표 중에서) 아직 끝내지 못한 부분: 기능 구현

### 2. 오늘 가장 의미있었던 기술적 판단
- 내가 내린 판단: 배차 동시성 처리 구현 방식을 구체화한 것: 주문 상태 변경과 라이더 상태 변경을 한 트랜잭션 내에서 각각 조건부 UPDATE한다.
- 그렇게 판단한 이유: 하나의 주문에 두 명이상의 라이더가 배정되는 문제와 한 명의 라이더가 동시에 두 개이상의 주문에 배정되는 문제를 처리하는 로직에 대한 혼돈이 있었다.
- 고려했지만 선택하지 않은 대안: 라이더 배차 시 두번째 문제에 대한 처리를 제외하는 것
- 이 판단이 코드 품질/테스트/유지보수에 미친 영향: 라이더, 주문 상태의 전이를 원자적으로 처리한다는 규칙을 명시적으로 드러내며, 보장한다.

### 3. 가장 막혔던 문제와 해결 과정
- 문제 상황 또는 증상: 하나의 주문에 두 명이상의 라이더가 배정되는 문제와 한 명의 라이더가 동시에 두 개이상의 주문에 배정되는 문제를 처리하는 로직에 대한 혼돈
- 처음 추측한 원인: 동시성 처리에 대한 이해도 부족
- 원인을 확인하기 위해 시도한 방법: AI와 토론
- 실제 원인: 이중 검증 로직
- 해결 방법: 문서화
- 다음에 비슷한 문제가 생기면 먼저 확인할 것: 관련 지식 습득

### 4. 오늘 잘한 행동(개발과 관련된 것)
- 어떤 행동이었는지: 안건을 Github Discussion으로 발행
- 그 접근이 도움이 된 이유: 안건에 대해 논의를 누락하는 문제 해결 및 논의 명시적 기록
- 다음에도 반복하고 싶은 점: 기록 도입 확장

### 5. 오늘 아쉬웠던 행동(개발과 관련된 것)
- 비효율적이었던 접근/놓치거나 부족했던 점: 팀원과 업무가 겹쳐서 하나를 폐기함
- 그렇게 된 원인: 소통 부족
- 다음에는 다르게 해볼 구체적인 행동: 할 일을 명시적으로 나누기
